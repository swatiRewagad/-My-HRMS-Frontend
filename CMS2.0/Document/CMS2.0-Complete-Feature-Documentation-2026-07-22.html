1. Public Complaint Portal

Public

The public-facing complaint filing system that allows citizens to register banking complaints under the RBI Integrated Ombudsman Scheme.

1.1 Eligibility Wizard (9-Question Flow)

Before filing, citizens must pass an eligibility check through a guided questionnaire:

#Question KeyPurpose
1regulatedEntitySelect the Regulated Entity type (Bank, NBFC, etc.)
2complaintAgainstConfirm complaint is against an RE covered under the scheme
3groundOfComplaintSelect category/ground of complaint
4filedWithREConfirm prior complaint was filed with the RE
5reResponseTimeRE did not respond within 30 days OR response was unsatisfactory
6pendingForumNot pending in any court/tribunal/arbitrator
7withinLimitationFiled within limitation period (1 year from RE response)
8notSettledNot already settled by Ombudsman
9consentConsent to declaration

Outcome: If any eligibility answer fails, the complaint is marked NON_MAINTAINABLE and the user is informed.

1.2 Multi-Step Complaint Form

After eligibility clearance, the form progresses through these steps:

  1. Step 1 - Complainant Details: Name, mobile, email, address, Pincode (auto-fills State/District)
  2. Step 2 - Entity Details: Select RE name, branch, state, district, credit card flag
  3. Step 3 - Complaint Details: Subject, description, category, dispute amount, date of cause
  4. Step 4 - Prior Complaint Info: RE complaint reference, date, RE response details
  5. Step 5 - Attachments: Upload supporting documents (max 10 files, 50MB each)
  6. Step 6 - Review & Submit: Preview all data, confirm, and submit

Validations: All mandatory fields (entityState, entityDistrict, entityBranch, isCreditCardComplaint, disputeAmount, bankComplaintDate) are enforced with inline error messages.

1.3 Complaint Tracking

Citizens can track complaint status using their complaint number or mobile number.

  • Real-time status updates with timeline visualization
  • View assigned officer (anonymized)
  • Download resolution letters
  • File appeal if unsatisfied with resolution

1.4 Complaint History

Authenticated citizens can view all their past complaints with status, dates, and outcome.

1.5 File Appeal

If a complaint resolution is unsatisfactory, citizens can file an appeal to the Appellate Authority within 30 days of the order.

1.6 Withdraw Complaint

Citizens can withdraw a pending complaint voluntarily before it reaches final resolution stage.

1.7 Submit Feedback

Post-resolution feedback submission with satisfaction rating.

2. Citizen Authentication & Session Management

Public

2.1 OTP-Based Authentication

  • Mobile number verification via 6-digit OTP
  • OTP validity: 10 minutes
  • Max resend: 99/hour (dev), configurable for prod
  • Max verify attempts per OTP: 99 (dev), 3 (prod)
  • Captcha validation before OTP request

2.2 Session Management (NFR-005)

  • 15-minute session timeout
  • Session ID tracked via X-Session-Id header
  • Auto-logout with warning dialog
  • Session binding to mobile number

2.3 Anti-Automation & Rate Limiting

  • CAPTCHA (image-based, 6 characters, 200x60px)
  • Form submission timing check (min-form-submission-ms)
  • Honeypot field detection (X-HP-Field header)
  • Velocity throttling (60s window, threshold: 100)
  • Cool-off progression: 5s, 10s, 20s (resets after 1 minute)
  • IP-based rate limiting for OTP requests

3. MRE (Maintainability Rules Engine)

Engine

3.1 How MRE Works

The MRE evaluates every incoming complaint against 6 grounds to determine if it's maintainable under the RBI-IOS 2026 rules.

Complaint Submitted MRE Evaluates 6 Grounds Generates Verdict per Ground Computes Overall Signal Routes to Officer

3.2 Six Grounds Evaluated

GroundRuleVerdict if Fails
ENTITY_NOT_COVEREDRE must be covered under the schemeNON_MAINTAINABLE
NO_PRIOR_RE_COMPLAINTMust have filed with RE firstNON_MAINTAINABLE
FILED_BEFORE_WINDOWMust wait 30 days after RE complaint (or RE replied)NON_MAINTAINABLE
FILED_BEYOND_DEADLINEMust file within 1 year of RE responseNON_MAINTAINABLE
RE_COMPLAINT_BEYOND_LIMITATIONRE complaint must be within 3-year limitationNON_MAINTAINABLE
SAME_GRIEVANCE_PENDINGSame issue not pending in court/tribunalNON_MAINTAINABLE

Logic: ANY single ground FAIL = Overall verdict OBJECTIVELY_NON_MAINTAINABLE

4. CRPC Module (Central Receipt & Processing Centre)

Staff

4.1 Overview

CRPC handles complaints received via Email and Physical Letters. It is the digitization and assessment layer before routing to RBIO/CEPC.

4.2 DEO (Data Entry Operator) Dashboard

  • View queue of unprocessed email drafts
  • Manual data entry for physical letters
  • OCR-assisted field extraction from scanned documents
  • Draft assessment: fill complainant details, entity info, complaint details
  • MRE copilot shows real-time maintainability assessment
  • Submit for reviewer approval or mark as non-maintainable

4.3 Reviewer Dashboard

  • Review DEO-submitted drafts
  • Approve (promotes to full complaint) or Reject (sends back to DEO)
  • Add comments and corrections
  • Threshold management: max 50 complaints per reviewer

4.4 In-Charge Dashboard

  • Workload overview across all DEOs and Reviewers
  • Reassign complaints between team members
  • View pending/overdue items
  • Threshold overflow management

4.5 Ops Head Dashboard

  • High-level operational metrics
  • View all complaints in pipeline
  • Escalation handling

4.6 Help Desk

  • Handle citizen inquiries about complaint status
  • Search and look up complaints
  • Provide status updates to citizens

4.7 Physical Letter Intake

Receive Letter Scan & OCR DEO Reviews Extraction Fills Missing Fields Submit for Review Route to RBIO/CEPC

4.8 Routing Logic

After CRPC approval, complaints are routed based on entity type:

  • Banking entities (banks, NBFCs, payment systems) → RBIO
  • Non-banking entities (card networks, system participants) → CEPC

5. RBIO Module (RBI Integrated Ombudsman)

Staff

5.1 Officer Dashboard

  • View assigned complaints with priority indicators
  • Round-robin auto-assignment from Keycloak user pool
  • SLA progress bars per complaint
  • Quick actions: Accept, Investigate, Escalate, Close

5.2 Complaint Detail & Actions

  • Full complaint timeline with all events
  • Communication with RE (send notices, reminders)
  • Communication with complainant
  • Add investigation notes
  • View similar past cases (OpenSearch)
  • AI Triage signal (priority recommendation)
  • Compensation calculation

5.3 Conciliation Process

  • Schedule conciliation meetings between complainant and RE
  • Record conciliation outcome
  • If conciliation fails, escalate to adjudication

5.4 Adjudication

  • Formal hearing process
  • Issue award/order
  • Generate closure letters
  • Award compensation if applicable

5.5 Supervisor Dashboard

  • Overview of all officers' workload
  • SLA breach monitoring
  • Reassign complaints
  • Approve high-value awards
  • View escalated cases

5.6 Advisory Generation

Generate formal advisories to regulated entities based on complaint patterns.

5.7 Assignment Logic

Round-robin assignment via ComplaintRoutingService:

  1. Query Keycloak for users with RBIO_OFFICER role
  2. Use atomic counter to select next officer in rotation
  3. If Keycloak unavailable, falls back to "RBIO OFFICER Team" (pool assignment)

10. AI/ML Features

AI

10.1 OCR Pipeline

Multi-provider OCR chain for extracting text from scanned documents:

ProviderUse Case
Groq (LLaMA 4 Scout)Primary: Fast AI-powered extraction
PaddleOCRFallback: Local, no API key needed
GeminiAlternative cloud provider
Azure Document IntelligenceEnterprise-grade extraction
OpenAI VisionGPT-4 based extraction
HuggingFaceOpen-source models

Configuration: cms.ocr.chain selects the active provider.

10.2 Intake Triage (AI Priority Signal)

  • Analyzes complaint text at intake
  • Assigns triage signal: HIGH, MEDIUM, LOW
  • Considers: dispute amount, complaint category, RE history, urgency keywords
  • Signal stored as triageSignal on complaint entity

10.3 MRE Copilot (Maintainability Assessment)

  • Real-time assessment shown during CRPC draft editing
  • Shows which grounds PASS/FAIL/INSUFFICIENT_DATA
  • Suggests corrections to make complaint maintainable
  • Runs via MaintainabilityCopilotService

10.4 Similar Cases (OpenSearch)

  • Full-text similarity search on complaint description
  • Shows past cases with similar facts for officer reference
  • Helps ensure consistent resolution
  • Configurable: cms.similar-cases.enabled

10.5 Compensation Precedent Service

Analyzes past awards for similar complaint types to recommend appropriate compensation ranges.

10.6 RE Responsiveness Scoring

Tracks and scores how responsive each RE is to Ombudsman communications, influencing triage and escalation.

12. Workflow Engine (BPMN/jBPM)

Engine

12.1 State Machine

Each complaint follows a defined lifecycle:

FILED ASSIGNED IN_PROGRESS AWAITING_RE_RESPONSE CONCILIATION ADJUDICATION RESOLVED/CLOSED

12.2 BPMN Process Definitions

  • RBIO complaint workflow (conciliation → adjudication)
  • CEPC complaint workflow
  • Appeal workflow
  • Escalation workflow
  • Defined in Camunda Modeler (camunda-modeler-setup/)

12.3 Task Management

  • Tasks auto-created from BPMN process nodes
  • Task assignment via round-robin or manual
  • Task actions: Claim, Complete, Delegate, Escalate
  • Task history and audit trail

13. SLA Monitoring & Escalation

Engine

13.1 SLA Calculation

  • Business hours only: 9 AM - 6 PM IST (configurable)
  • Excludes holidays (from Holiday entity)
  • Default SLA: 240 business hours (30 working days)
  • TAT (Turn-Around Time) calculated in real-time

13.2 Escalation Rules

  • Auto-escalation on SLA breach
  • Multi-level escalation: Officer → Supervisor → In-Charge → Head
  • Configurable escalation thresholds per complaint priority
  • Email/notification triggers on escalation

13.3 CEPC SLA Service

Dedicated SLA tracking for CEPC with different thresholds and business rules.

13.4 RBIO SLA Service

RBIO-specific SLA with conciliation and adjudication phase timers.
