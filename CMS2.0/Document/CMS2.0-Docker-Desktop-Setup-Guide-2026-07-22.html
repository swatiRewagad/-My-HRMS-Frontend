1.3 Docker Desktop Configuration

  1. Open Docker Desktop → Settings → Resources
  2. Set Memory: 10 GB (minimum for full stack)
  3. Set CPUs: 4+
  4. Set Disk image size: 40 GB
  5. Enable WSL2 based engine (Windows)
  6. Click "Apply & Restart"
If running with limited RAM (8 GB), use the "Lite" profile that excludes OpenSearch, Grafana, and PaddleOCR (Section 5).

# Navigate to infrastructure directory

7. Keycloak Configuration (Docker)

In Docker mode, Keycloak runs on port 8180 (not 9090 like local dev).

1 Access Keycloak Admin

# Open in browser
http://localhost:8180

# Login: admin / admin

2 Setup via kcadm CLI inside container

# Execute kcadm inside the Keycloak container
docker exec -it cms-keycloak bash

# Inside container:
/opt/keycloak/bin/kcadm.sh config credentials \
  --server http://localhost:8180 --realm master --user admin --password admin

# Create 'cms' realm
/opt/keycloak/bin/kcadm.sh create realms -s realm=cms -s enabled=true

# Create client
/opt/keycloak/bin/kcadm.sh create clients -r cms \
  -s clientId=cms-frontend -s enabled=true -s publicClient=true \
  -s directAccessGrantsEnabled=true \
  -s 'redirectUris=["http://localhost/*","http://localhost:4200/*"]' \
  -s 'webOrigins=["http://localhost","http://localhost:4200"]'

# Create roles
/opt/keycloak/bin/kcadm.sh create roles -r cms -s name=RBIO_OFFICER
/opt/keycloak/bin/kcadm.sh create roles -r cms -s name=RBIO_SUPERVISOR
/opt/keycloak/bin/kcadm.sh create roles -r cms -s name=DO
/opt/keycloak/bin/kcadm.sh create roles -r cms -s name=REVIEWER
/opt/keycloak/bin/kcadm.sh create roles -r cms -s name=ADMIN
/opt/keycloak/bin/kcadm.sh create roles -r cms -s name=SENIOR
/opt/keycloak/bin/kcadm.sh create roles -r cms -s name=RE_NODAL_OFFICER

# Create test user
/opt/keycloak/bin/kcadm.sh create users -r cms \
  -s username=officer.rbio1 -s enabled=true -s firstName=RBIO -s lastName=Officer1
/opt/keycloak/bin/kcadm.sh set-password -r cms --username officer.rbio1 --new-password Test@1234
/opt/keycloak/bin/kcadm.sh add-roles -r cms --uusername officer.rbio1 --rolename RBIO_OFFICER

# Exit container
exit
Tip: Export the realm config as JSON and mount it as a volume for automatic setup on fresh deployments.

8. Common Docker Operations

8.1 Service Management

# Stop all services
docker compose down

# Stop and remove volumes (DELETES ALL DATA)
docker compose down -v

# Restart a specific service
docker compose restart cms-backend-1

# Rebuild and restart a service (after code changes)
docker compose up --build -d cms-backend-1

# Scale backend to 3 instances
docker compose up -d --scale cms-backend-1=3

# View resource usage
docker stats

8.2 Logs & Debugging

# View all logs
docker compose logs -f

# View specific service logs (last 100 lines)
docker compose logs -f --tail=100 cms-backend-1

# Enter a container shell
docker exec -it cms-backend-1 sh

# View Kafka topics
docker exec -it cms-kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --list

# Consume Kafka messages (live)
docker exec -it cms-kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 --topic complaint.ingested --from-beginning

# MySQL CLI
docker exec -it cms-mysql mysql -u cms_user -pcms_pass cms_db

# Redis CLI
docker exec -it cms-redis redis-cli

8.3 Database Operations

# Backup MySQL database
docker exec cms-mysql mysqldump -u root -pcms_root_pass cms_db > backup.sql

# Restore MySQL database
docker exec -i cms-mysql mysql -u root -pcms_root_pass cms_db < backup.sql

# Run init SQL (seed data)
docker exec -i cms-mysql mysql -u cms_user -pcms_pass cms_db < database/init.sql

8.4 Rebuilding After Code Changes

# After backend code changes:
docker compose up --build -d cms-backend-1 cms-backend-2

# After frontend code changes:
docker compose up --build -d cms-frontend

# Rebuild all services:
docker compose build --no-cache
docker compose up -d

# Clean up dangling images:
docker image prune -f

9. Dockerfile Details

9.1 Backend Dockerfile

File: cms-backend/Dockerfile
Strategy: Multi-stage build (build with JDK 21, run with JRE 21 Alpine) 
# Stage 1: Build with Maven
FROM eclipse-temurin:21-jdk-alpine AS build
WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN apk add --no-cache maven && mvn clean package -DskipTests -q

# Stage 2: Lightweight runtime
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
RUN addgroup -S cms && adduser -S cms -G cms
COPY --from=build /app/target/*.jar app.jar
RUN mkdir -p /cms-attachments && chown cms:cms /cms-attachments
USER cms
EXPOSE 8082
HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
  CMD wget -qO- http://localhost:8082/actuator/health || exit 1
ENTRYPOINT ["java", "-XX:+UseG1GC", "-XX:MaxGCPauseMillis=200", \
  "-XX:+UseStringDeduplication", "-XX:InitialRAMPercentage=50.0", \
  "-XX:MaxRAMPercentage=75.0", "-Djava.security.egd=file:/dev/./urandom", \
  "-jar", "app.jar"]

9.2 Frontend Dockerfile

File: cms-portal-frontend/Dockerfile
Strategy: Multi-stage build (build with Node 22, serve with Nginx 1.27) 
# Stage 1: Build Angular app
FROM node:22-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --prefer-offline --no-audit
COPY . .
ARG NG_CONFIG=openshift
RUN npx ng build --configuration=${NG_CONFIG}

# Stage 2: Serve with Nginx
FROM nginx:1.27-alpine
RUN rm /etc/nginx/conf.d/default.conf
COPY nginx.conf /etc/nginx/conf.d/default.conf.template
COPY docker-entrypoint.sh /docker-entrypoint.sh
RUN chmod +x /docker-entrypoint.sh
COPY --from=builder /app/dist/cms-portal-frontend/browser /usr/share/nginx/html
RUN addgroup -S frontend && adduser -S frontend -G frontend && \
    chown -R frontend:frontend /var/cache/nginx /var/log/nginx /etc/nginx/conf.d
USER frontend
ENV API_BACKEND_HOST=cms-backend
ENV API_BACKEND_PORT=8080
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD wget -qO- http://localhost:80/healthz || exit 1
ENTRYPOINT ["/docker-entrypoint.sh"]

9.3 Frontend docker-entrypoint.sh

#!/bin/sh
# Substitutes environment variables into nginx config at runtime
envsubst '${API_BACKEND_HOST} ${API_BACKEND_PORT}' \
  < /etc/nginx/conf.d/default.conf.template \
  > /etc/nginx/conf.d/default.conf

# Start Nginx in foreground
exec nginx -g 'daemon off;'

12. Troubleshooting

Error: "port is already allocated"

Fix: Another service is using the port. Find and stop it:

netstat -ano | findstr :8080
taskkill /PID <PID> /F

Error: Backend fails to connect to MySQL

Fix: MySQL may still be initializing. Wait for health check to pass:

docker compose logs -f cms-mysql
# Wait for: "ready for connections"

Error: Kafka "broker not available"

Fix: Kafka takes 30-60s to start in KRaft mode. Check logs:

docker compose logs -f cms-kafka
# Wait for: "Kafka Server started"

Error: Out of memory / Container OOM killed

Fix: Increase Docker Desktop memory allocation (Settings → Resources → Memory). Or use the Lite profile (Section 5).

Error: Build fails "npm ERR! code ERESOLVE"

Fix: Clear npm cache and rebuild:

docker compose build --no-cache cms-frontend

Error: Keycloak "Failed to initialize realm"

Fix: Keycloak DB (Postgres) may not be ready. Restart Keycloak after DB is healthy:

docker compose restart cms-keycloak

Error: Frontend shows blank page / 502 Bad Gateway

Fix: Backend may still be starting (60s startup). Check health:

curl http://localhost:8080/actuator/health
