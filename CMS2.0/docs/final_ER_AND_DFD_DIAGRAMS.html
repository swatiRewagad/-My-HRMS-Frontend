5. DFD: Feature 3 — Complaint Number Generation

FEATURE 3 Number Format: N + FY(6) + OfficeCode(3) + Sequence(6) → e.g. N202627013000001 
INPUT: department, complainantState, complainantDistrict, isVernacularOrCrpc

┌─────────────────────────────────────────────────────────────────────────────────────┐
│  STEP 1: resolveOfficeName(department, state, district)                             │
│                                                                                     │
│  ┌────────────────────────────────────────────────────────────────────────────────┐ │
│  │  D8: OMBUDSMAN_OFFICE_MASTER (24 offices with jurisdiction text)               │ │
│  │                                                                                │ │
│  │  Algorithm:                                                                    │ │
│  │  1. Search DISTRICT in jurisdiction text (handles Mumbai-I/II split)           │ │
│  │  2. If no unique match → search STATE name                                    │ │
│  │  3. Multiple matches → parse "excluding"/"except" clauses                     │ │
│  │     Example: UP → Dehradun (7 districts) / Kanpur (rest) / New Delhi-II (2)   │ │
│  │  4. Fallback → "New Delhi I"                                                  │ │
│  └────────────────────────────────────────────────────────────────────────────────┘ │
│                                                                                     │
│  STEP 2: resolveOfficeCode(officeName)                                              │
│                                                                                     │
│  ┌────────────────────────────────────────────────────────────────────────────────┐ │
│  │  D9: OFFICE_CODE_MASTER                                                        │ │
│  │  • Exact match: officeName where isActive=true                                 │ │
│  │  • Fallback: replace hyphen→space ("Mumbai-I" → "Mumbai I")                   │ │
│  │  • Default: code "014" (New Delhi I)                                           │ │
│  └────────────────────────────────────────────────────────────────────────────────┘ │
│                                                                                     │
│  STEP 3: applyThresholdOverflow(officeCode)  [SKIP if vernacular/CRPC]             │
│           → See Feature 4 DFD below                                                 │
│                                                                                     │
│  STEP 4: getNextSequence(assignedOfficeCode, financialYear)                         │
│                                                                                     │
│  ┌────────────────────────────────────────────────────────────────────────────────┐ │
│  │  D12: COMPLAINT_NUMBER_SEQUENCE                                                │ │
│  │  • PESSIMISTIC_WRITE lock (thread-safe, no duplicates)                         │ │
│  │  • Atomic increment of LAST_SEQUENCE                                           │ │
│  │  • New row auto-created for new office+FY combination                          │ │
│  └────────────────────────────────────────────────────────────────────────────────┘ │
│                                                                                     │
│  STEP 5: Format output                                                              │
│  ┌────────────────────────────────────────────────────────────────────────────────┐ │
│  │  String.format("N%s%s%06d", financialYear, officeCode, sequence)               │ │
│  │  Example: "N" + "202627" + "013" + "000001" = N202627013000001                 │ │
│  └────────────────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────────────┘

FINANCIAL YEAR LOGIC:
┌────────────────────────────────────────────────────┐
│  Month >= 4 (Apr-Mar):  year + (year+1)%100        │
│    Aug 2026 → "202627"                             │
│                                                    │
│  Month < 4 (Jan-Mar):  (year-1) + year%100         │
│    Jan 2027 → "202627"                             │
└────────────────────────────────────────────────────┘

FEATURE 4 Load balancing across offices — priority-based overflow when threshold met 
INPUT: targetOfficeCode (from Step 2)

┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                                                                                             │
│  ┌───────────────────────────────────────┐       ┌───────────────────────────────────────┐  │
│  │ Read Global Threshold                  │──────▶│ D11: OFFICE_GLOBAL_THRESHOLD_CONFIG   │  │
│  │ (Super Admin configurable, default=2)  │◀──────│      id=1, thresholdValue=2           │  │
│  └──────────────────┬────────────────────┘       └───────────────────────────────────────┘  │
│                     │                                                                       │
│  ┌──────────────────▼────────────────────┐       ┌───────────────────────────────────────┐  │
│  │ Lock target office FOR UPDATE          │──────▶│ D9: OFFICE_CODE_MASTER                │  │
│  │ Read: target.counter                   │◀──────│     (officeCode, counter, threshold)  │  │
│  └──────────────────┬────────────────────┘       └───────────────────────────────────────┘  │
│                     │                                                                       │
│          ┌──────────┴──────────┐                                                           │
│          │ counter < threshold?│                                                           │
│          └──────────┬──────────┘                                                           │
│            YES │         │ NO                                                              │
│                │         │                                                                  │
│                ▼         ▼                                                                  │
│  ┌──────────────────┐  ┌─────────────────────────────┐  ┌────────────────────────────────┐ │
│  │ target.counter++ │  │ Lookup overflow mapping      │─▶│ D10: OFFICE_OVERFLOW_MAPPING   │ │
│  │ RETURN target    │  │ for this officeCode          │◀─│     priority1, priority2       │ │
│  └──────────────────┘  └──────────────┬──────────────┘  └────────────────────────────────┘ │
│                                       │                                                    │
│                            ┌──────────┴──────────┐                                         │
│                            │ P1.counter<threshold?│                                         │
│                            └──────────┬──────────┘                                         │
│                              YES │         │ NO                                            │
│                                  ▼         ▼                                               │
│                    ┌──────────────────┐  ┌──────────────────┐                              │
│                    │ p1.counter++     │  │ P2.counter<threshold?│                           │
│                    │ RETURN priority1 │  └──────────┬──────────┘                           │
│                    └──────────────────┘    YES │         │ NO                              │
│                                               ▼         ▼                                 │
│                                 ┌──────────────────┐  ┌─────────────────────────────────┐  │
│                                 │ p2.counter++     │  │ ALL 3 OFFICES MET THRESHOLD     │  │
│                                 │ RETURN priority2 │  │                                 │  │
│                                 └──────────────────┘  │ RESET all 3 counters → 0        │  │
│                                                       │ target.counter = 1              │  │
│                                                       │ RETURN target                   │  │
│                                                       └─────────────────────────────────┘  │
│                                                                                             │
│  ╔═══════════════════════════════════════════════════════════════════════════════════════╗   │
│  ║  EXCEPTION: Vernacular (EMAIL) and CRPC (PHYSICAL_LETTER) complaints               ║   │
│  ║  → Bypass this entire logic. Direct assignment. No counter impact.                  ║   │
│  ╚═══════════════════════════════════════════════════════════════════════════════════════╝   │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
